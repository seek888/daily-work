# 调度器离线实证（Scheduler Proof）

> 目的：`DESIGN.md` §9.3 的调度语义此前只有文字。本文件把 6 条语义（9 条断言）钉成**可复跑**的证明。
> 脚本：`proof/scheduler-proof.mjs`（纯 Node ≥20，零依赖，无网络，不连 DSH）。
> 运行：`node proof/scheduler-proof.mjs`，任一断言失败退出码非 0。**本次结果：9/9 PASS，exit 0。**

## 1. 被证明的语义

| # | 断言 | 对应设计 |
|---|---|---|
| S1 | 同一到期只产生一个 Run；重复 tick 不重复跑 | 幂等键 `jobId + scheduledAt` |
| S1b | 下个周期正常再跑 | 窗口推进 |
| S2 | 同 `laneKey` 串行（时间线不重叠） | lane 串行 |
| S3 | 不同 lane 可并行（存在重叠） | 并发上限 |
| S4 | 错过 5 期、`catchUp=skip` 不补跑，窗口推进到下一个未来时刻 | 补跑策略 |
| S5 | 错过 5 期、`catchUp=run-once` 只补 1 次，窗口同样推进到未来 | 补跑策略 |
| S6 | after 链第 9 跳被熔断，只记录不派发 | 8 跳熔断（借 autoloop） |
| S7 | 重启把 `running` 标为 `interrupted` 并按策略重试一次 | 重启恢复 |
| S7b | 重试只产出一个产物，不重复 | 不重做业务 |

## 3. 这套证明覆盖了什么、**没有**覆盖什么

**覆盖（纯语义层）**：幂等、窗口推进、lane 串行、跨 lane 并行、两种补跑策略、after 链熔断、重启后的 interrupted + 单次重试、不重复产出。

**没有覆盖（必须在 M4 用真宿主验证）**：

1. **真实 `ctx.timer` 漂移**：脚本用虚拟时钟，宿主定时器会迟到/合并，30s tick 实际可能是 31–45s。
2. **`storageDomain` 事务与多窗口**：脚本是单进程互斥；宿主可能同时有桌面窗口 + 浏览器标签，需要真实的「单事务加锁」。
3. **系统休眠/关机**：脚本模拟「错过 5 期」，但没有真实挂起恢复的时序。
4. **多路 `agents.create` 并发**：脚本里的任务只 sleep；真实并发起 3 个 Session 是否互相影响（内存、模型限流、文件锁）未验。
5. **`worktrees` 隔离**：写任务的隔离目录没有在这里出现。

## 4. 给 M4 的三条实测建议

1. **用假 Job 跑真 tick**：注册一个 10 秒间隔、durMs=1s 的假 Job，连跑 10 分钟，记录实际触发时刻与漂移分布（期望 ≤ 2s）。
2. **双窗口同开**：桌面窗口 + 浏览器标签同时打开面板，验证同一到期只跑一次（把 idem 键打到日志里对账）。
3. **人为错过窗口**：关闭 Harness 20 分钟再启动，分别验证 `skip`（不补）与 `run-once`（只补一次），并检查「上次运行/下次运行」显示是否正确。

## 5. 判断

调度语义本身已经可以按这个脚本的行为去实现；剩下的是宿主适配问题，不是设计问题。M4 的验收标准可以以此表的 9 条为基线 + 上面 3 条实测。
